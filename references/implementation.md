# 实现参考

这里记录容易影响正确性的实现选择。按输入资料和本机工具调整，不要求固定技术栈。

## 中间数据与断点续跑

每份原件保存稳定 ID、相对源路径、文件类型、大小和修改时间或内容哈希。PDF 每页单独记录页码、处理方式（文字层／本机 OCR／原图保留／局部补转录）、输出路径、审校状态和问题。先把提取结果写到独立的中间文件，再从中间数据生成 HTML。重新生成页面时，目录和学习功能也一并生成，避免手工注入的导航被覆盖。

失败只影响对应文件或页；记录原因并允许重跑。不要在合并失败时把已有成品换成空白页。源文件更改后，识别受影响的任务再重做。

## PDF 与媒体

按页判断文字层是否可用：空白、明显乱码、错序、多栏串行、代码缩进丢失时转本机 OCR。OCR 有置信度就记录；没有置信度时根据异常短页、重复字、不可读字符和视觉抽查标记待核对。不要凭单个阈值断定整份 PDF 都适合同一种方法。

表格、代码、公式、图表和图片里的小字最容易出错。对于视觉信息，保留局部裁图或原页查看入口；文本与同一整页图重复时，优先保留文字和必要的局部图。保留原始页码，别把网站页序当成 PDF 页码。

视频优先保留播放器和原件链接。需要转录时，使用本机模型生成带时间戳的文本或字幕；先检查音轨、语言、噪声和分段，抽听几处。浏览器不支持的媒体格式只给下载或打开原件的链接，不承诺内嵌播放。

## 在线审校的范围

先运行确定性检查：源页数与输出页数、页码序列、文本为空或异常短、资源缺失、图文重复、章节锚点失效。再挑选疑难页、复杂布局页和每类资料的随机样本做视觉对照。用户允许在线大模型时，仅把这些页所需的图片和候选文字发送给它，要求指出具体不符之处、页码和证据；修复后重查。审校报告区分“程序全量检查”“模型抽样审校”“人工核对”。

如果抽样发现系统性错误，扩大同类页面的审校范围并调整本机提取规则。不能用一次抽样通过来宣称全文准确。

## `file://` 网站约束

- 首页、阅读页和练习页用相对链接；资源文件名做好 URL 编码或使用安全生成名，并检查每个链接目标存在。
- 页面数据可直接生成到 HTML 或普通脚本变量；不要让正文依赖 `fetch()`、模块加载、服务端 API 或客户端路由。
- 对提取文字进行 HTML 转义；以文本方式显示代码，避免把源文档中的标签执行为脚本。
- 原生 JavaScript 的笔记功能可用本地存储，但要有导出／导入。`file://` 的存储按浏览器和打开路径可能改变；状态显示应能容忍存储不可用。
- 如果站点留在原资料文件夹内，可用相对链接指向原媒体；需要可移动的独立成品时，再复制所需资源。复制前估算视频体积。
- 最终在文件管理器中双击 `site/index.html` 验收，至少覆盖首页、一份长文档、一个视觉页、一个媒体入口和笔记导出／导入（如启用）。临时 HTTP 服务只能作为附加的手机访问验证。
