# 学习计划：目录上的 Week/Day 小标题

## 为什么要有

网盘课程动辄上百个文件，平铺目录只能"存着"，不能"学着"。给目录打上 Week N / Day N
的小标题，学习者每天打开就知道该看哪几节、看多久——站点从"资料库"变成"课程表"。

## 两条硬规则

### 规则一：目录顺序 = 集数数字序（自然排序）

网盘课程的文件名几乎都带集数前缀（`1.xxx`、`10.xxx`、`100.xxx`）。字典序会把
`10`、`100` 排到 `2` 前面，学习顺序全乱。`build_site.py` 的 `nat_key()` 已统一按
文件名开头数字排序（`1,2,...,10,11`），文件和子目录两条路径都生效。自写脚本遍历
资料时同样必须用数字序，不要用字典序。

注意：改排序会改变 slug 分配（`w02-003` 从此对应不同的文件）。已有成品页和按 slug
命名的衍生文件（转录片段、转录 JSON 等）要按 `manifest.src`（源文件相对路径）重新
映射到新 slug 后再合并，否则会张冠李戴。

### 规则二：按「每天约1小时（含知识内化）」规划 Week/Day

每天 1 小时学习时间不等于 1 小时视频——必须给笔记和内化留时间。默认节奏：
**视频约 25 分钟 + 笔记内化约 35 分钟**。

`make_plan.py`（复制到课程根目录，与 build_site.py 同目录）自动打包：

1. 读 `site/_manifest.json`，探测 mp4 时长（优先复用 `site/_asr/durations.json`，
   否则用 av 探测，都没有就按体积估算）。
2. 从标题提取章节号（`【公式3】`/`【案例3-7】`→ 第3章，容忍括号内空格），连续同章
   条目合成学习模块；无标签条目自成模块（如先导片）。
3. 模块按时长贪心装入天：加上本模块会超过 `--day-minutes`（默认25）就另起一天。
   想让"一个知识模块恰好一天"，把预算设成单模块时长上界即可。
4. 每 `--week-days` 天合为一周；周标题按本周覆盖的章节段落映射到 `--modules`
   给出的阶段名（跨阶段用 → 连接），无阶段映射时只标章节范围。

```bash
python make_plan.py --day-minutes 25 --week-days 6 \
  --modules "1-2:模块一 建立你的能量场;3-12:模块二 减少能量耗损;13-28:模块三 提升你的能量;29-32:模块四 成事之道"
```

产出 `site/_plan.json`；下次跑 `build_site.py index`（或 merge/videos）时目录自动
按 Week/Day 渲染。每个 Day 行会显示实际视频分钟数和建议配套的内化分钟数
（两者合计约 1 小时）。

`--modules` 的阶段划分从哪来：先导片/大纲文档里通常有（如"这套课包括四个模块…"），
读先导资料的转录或目录即可提炼；提炼不出来就省略该参数，周标题退化为章节范围。

## 节奏参数怎么调

| 场景 | day-minutes | week-days |
|---|---|---|
| 内容密、想学透（默认） | 25 | 6（留1天复习缓冲） |
| 视频短、案例多 | 30~40 | 6~7 |
| 时间紧、只想过一遍 | 45 | 7 |

## 校验

- 目录上 Week 小节数 = `ceil(天数/week-days)`，Day 头部数 = 天数，条目数不变；
- 条目按集数严格递增（抽查首尾与任意跳变处）；
- `_plan.json` 里的 slug 全部能在 manifest 中找到；`build_site.py index` 后无
  「其他资料」残留分组（有则说明 plan 未覆盖全部条目）。
