# 阶段一执行细节：建站与转录

## 准备（调度智能体自己做）

1. 复制 `scripts/build_site.py` 到课程根目录，改文件头两个常量：`COURSE_TITLE`、`WEEK_DIR_RE`（默认 `^\d+\.` 匹配 `01.xxx`；课程若按「第1周」等方式命名就改成 `^第\d+周`——脚本取目录名里第一个数字串当周号，两种命名都能解析）。页数以 PDF 原件为准（脚本直接读 PDF），不靠数磁盘截图。`site/_manifest.json` 只存相对路径（`src` 相对课程根目录，`html`/`imgdir` 相对 `site/`），便于搬迁、不泄露本机目录结构；`_agent_prompts.txt` 里是绝对路径（给子代理 Read 用），**外发或开放站点前删除该文件**。
2. 跑 `build`，读输出确认三件事：渲染总页数、manifest 条目数、任务数（`_agent_prompts.txt` 里 `===` 的个数）。
3. 建状态文件 `site/_qc/status.md`（阶段一转录与阶段二质检共用）：每个转录任务一行，`| 任务 | 页范围 | 状态(pending/running/done/failed) | 备注 |`。派发即更新，断点续跑靠它。

## 派发转录子代理

- 每条任务提示词已由脚本生成在 `site/_agent_prompts.txt`：源 PDF 绝对路径、负责的截图范围、输出片段路径齐全，文件尾附转录规则全文。逐条复制派发即可，不需要自己写提示词。
- 工具名（Read/Write/Edit/Agent）按你的宿主智能体自行对应；宿主没有子智能体机制时退化为串行逐任务执行，其余流程不变。
- 调度纪律：
  - **≤5 并发**（`run_in_background` 派发），完成一个立刻补派；
  - 限流失败（报错含 1302 / rate limit / 429）：等 60~120 秒重试同一任务，最多 2 次，仍失败记入状态文件，最后统一补跑；
  - 每完成一个任务就跑一次 `merge` + `index`，让目录页实时反映进度；
  - 子代理汇报须含「输出路径 + 文字页数 + 嵌图页数 + 跳过页」；核对片段文件确实存在、页码覆盖对得上，再把状态标 done。

## 转录规则要点

规则全文内置在 `build_site.py` 的 `RULES` 常量里（会自动附在每个任务后），核心是：

- 每页一个 `<section class="page">`，首行 `<p class="pageno">第 NN 页</p>`（真实页码，两位数字）；
- 文字页转结构化 HTML，视觉页嵌整页截图，图文混合页两者都要——重复问题留给阶段二，转录子代理不做裁剪决策；
- 忠实原文，认不出写「（原文模糊）」，宁保留图不编造文字。

## 按课程类型选择首轮策略

「文字转录 + 嵌整页图」的粗规则适合难以快速判型的图文混合课件，不是所有课程都最优。**开工先取每类 5~10 页试运行**，再定全量策略：

| 课程类型 | 首轮策略 | 二次质检重点 |
|---|---|---|
| 可选中文字的讲义 | 优先提取 PDF 文字层并核对顺序/表格，只为真实图形留图 | 漏字、错序、表格与脚注 |
| 图文混合课件 | 转录文字 + 嵌整页图（本技能默认路径） | 图文重复、裁剪边界、截图内内容性文字 |
| 图表/流程图密集 | 保留完整关系图，同时转录标题、数据和关键说明 | 裁剪是否破坏图例、坐标及上下文 |
| 扫描件 | 每页原图作核对依据，先抽样评估识别质量再批量 | 清晰度、漏页、识别错误；核对前不删原图 |
| pptx/音视频为主 | pptx 加专用转换器；音频按时间戳 ASR + 抽查 | 幻灯片备注、可播放性、转写准确性；页图流程不适用 |

## merge / fallback / index 的语义（防丢页三道闸）

1. `merge`：某份 PDF 的所有片段按 part 顺序拼接后，页码必须**按阅读顺序恰为 1..pages** 才拼装成品页并删除片段——缺页、重复页、错序页一律拒绝，片段保留待修复，并在控制台列出问题。半成品和坏结构永远不进成品页。
2. **已存在的成品页一律不覆盖**——既保护转录产物，也让重复运行天然安全。
3. `fallback`：为还没有成品页的 PDF 生成整页图兜底页，并在 `</head>` 后加 `<!-- img-fallback -->` 标记。兜底页可被 merge 覆盖。想「先有站再慢慢转录」就先跑 fallback。
4. `index`：未完成条目显示「转录中」徽章；同时清理未被引用的原始页图，但**只清理已确认完成转录的 PDF**——还没转录或仍是兜底页的 PDF，页图全部保留（后续分块转录和阶段二质检随时要回读原图）。注意：被裁剪图替换掉的原始页图会在清理时永久删除，若预期之后还要重跑质检，先备份 `assets/img/`。

## 各类型资料的转换细节

- **PDF**：pymupdf 以 2 倍率渲染 `p-NN.png`；已存在的页图跳过（断点安全）。
- **docx**：mammoth 转 HTML（转换警告打印前 3 条）。
- **txt**：依次尝试 utf-8 → gb18030 → utf-16 解码（中文 Windows 的 txt 常是 gb18030），HTML 转义后放 `<pre>`。
- **mp4**：`<video controls>` 相对路径内嵌播放；**ts**：浏览器不能直接播，给下载链接（提示用 VLC/PotPlayer 打开）；**jpg**：直接 `<img>`。
- 未识别的扩展名（如 pptx）：要么给脚本加转换器，要么保持原件不建页——**不要生成空页充数**。

## 阶段一收口标准

- 每份 PDF 成品页：section 数 = 页数，页码按阅读顺序恰为 1..页数，无断图；无 `<!-- img-fallback -->` 残留（除非用户接受纯图页）。
- `index.html` 条目数 = manifest 条数。
- 状态文件无 pending/running/failed 残留。
