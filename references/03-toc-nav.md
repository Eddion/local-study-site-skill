# 阶段三执行细节：长课件章节侧边导航

## 触发条件

≥60 页的 PDF 成品页。短课件加导航收益低，跳过。

## 注入流程

1. **归纳结构**（子代理）：通读成品页正文，归纳章级标题清单（h2 级）。**宁缺毋假**：依据正文实际内容归纳，不得为了目录完整编造章节。归纳结果落盘 `site/_toc/toc-<slug>.md`（toc-N → 章标题对照清单）——成品页日后若损坏需重建，按清单重放注入即可，不必重新通读归纳。
2. **打锚点**：给每章标题 h2 加 `id="toc-N"`（N 从 1 递增）；正文缺章标题处补插 `<h2 id="toc-N">章名</h2>`。
3. **注入组件**（每页恰好一次）：在 topbar 之后、`<main>` 之前注入内嵌 `<style>`（tocnav 全套样式，含窄屏折叠到顶部）+ `<nav class="tocnav"><ul><li><a href="#toc-N">标题</a>…</ul></nav>`。
4. **校验**：把 `scripts/verify_toc.py` 复制到课程根目录（与 build_site.py 同处），运行 `python verify_toc.py site`（或加文件参数只查指定页），全部 OK 才算过。
5. **截图验收**：无头浏览器或人工对每份长课件截宽屏/窄屏各一张，存 `site/_toc/shots/`；状态记入 `site/_toc/status.md`。

## 铁律（重建覆盖问题）

- **导航直接写进成品 HTML，导入后冻结 `build_site.py` 的页面模板**——之后重跑任何会重建页面的命令都会把导航冲掉。需要改样式时改内嵌样式，不改构建脚本。
- **样式必须内嵌**进每个 HTML：不依赖外部 css 的改动，防重建覆盖。
- **注入要幂等**：注入前先检查该页是否已有 `tocnav`（重复注入会让校验失败）；每页恰好一个 nav、一对 style。

## verify_toc.py 校验什么

- `tocnav` 恰好 1 个；`<style>` 标签成对出现。
- 锚点 1:1 配对：无重复 id、无悬空链接（href 指向不存在的 id）、无未被链接的孤儿 id、无两个条目重复链接到同一锚点。
- 位置正确：nav 在 topbar 之后、`<main>` 之前。
- **链接文字与目标 h1/h2 标题逐字一致**——这是最容易翻车的项：归纳时改写了标题措辞就会挂。
