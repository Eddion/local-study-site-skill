# 阶段二执行细节：图文去重质检

## 为什么必做

阶段一的「文字 + 整页截图」粗规则保证不丢内容，代价是图文混合页大量重复。实测 1298 页的分布：**A（纯文字）23 / B（文字+视觉素材）893 / C（视觉为主）10 / D（无问题）372**——B 类占 69%，阶段二的工作量与阶段一同量级。跳过它，站点「能看但难读」：同样的内容要看两遍。注意这个比例只代表图文密集型课程；文字型课程的 B 类会少得多，实际预算以本课程的普查结果为准。

## 角色与流程（你是调度智能体，不亲自修）

1. **准备**：读 `site/_manifest.json`，取全部 `ext=="pdf"` 条目；建 `site/_qc/`，状态文件 `status.md` 每份 PDF 一行：`| slug | pages | 普查状态 | 修复状态 | 备注 |`。每派发/完成一个任务就更新。
2. **普查**（子智能体，产出问题清单）：每任务覆盖 ≤80 页；<30 页的小 PDF 可两三份合并一个任务；超过 80 页的 PDF 按连续页段拆成多个任务，**每段报告单独命名 `reports/{{slug}}.p起-止.md`**（实战 16 份 PDF 拆出 25 份报告就是这么来的），绝不能都写 `{{slug}}.md` 互相覆盖；修复时把该 slug 的全部页段报告一起交给修复子代理。
3. **修复**（子智能体，按报告执行）：普查完成一份就派一份（全部 D 的跳过并更新状态）。
4. **验收**（你自己做）：全量校验 + 起服务抽查 + 状态收口。

完整可填空的调度提示词（含普查/修复子代理模板和校验脚本）见 `templates/qc-dispatcher-prompt.md`。

## A/B/C/D 判型标准

普查子代理逐页对照成品 HTML 与原始截图，每页判型：

- **A 纯文字页**：文字已全部转录、无有价值视觉素材 → 应删整页图 figure。
- **B 文字+视觉素材**：文字已转录，页面含真正的视觉素材（产品截图、演示画面、图表、照片）→ 给出裁剪区域（用百分比描述在整页图中的位置，如「下半部分 45%~95%」「右侧 55%~100%」），并指出页面上还没转录的内容性文字。
- **C 视觉为主页**：复杂图形排版/整页信息图/照片拼贴 → 保留整页图，补转录图中内容性文字（标题、要点、数据）；纯 UI 元素（菜单栏、按钮、地址栏）不转录。
- **D 无问题**：处理已符合标准。

**特例**：截图里嵌套截图（软件演示、AI 对话面板）中的大段内容性回答/代码，若正是课件想传达的内容，必须忠实转录出来——这是最容易漏的内容。

## 修复纪律

- **只用 Edit 精准替换**（old_string 取含 pageno 的完整小段保证唯一），禁止重写整个文件、禁止动 section 结构、页码、页尾 ainote。
- **裁剪**：先 Read 原图确认尺寸与素材位置，再按报告百分比换算像素用 pillow crop，存 `p-NN-crop.png`（一页多块素材存 -crop1/-crop2）；HTML 改引裁剪图，原 `p-NN.png` 保留不删。
- **补转录**：忠实原文插入 figure 之前或之后，不编造、不解释。
- **每份修完自检三件套**：section 数不变、页码数不变、无断图（HTML 引用的每个图片文件必须真实存在）。不通过就修到通过。

## 验收

1. 全量校验：所有 PDF 成品页**页码按阅读顺序**完整（1..pages，直接按文档顺序比对，绝不先排序——排序会掩盖错序，实战 w11-051 的第 121-126 页就曾被排到 127-136 之后而没被发现）、无断图，输出 ALL OK（脚本见模板文件第 3 步）。ALL OK 的含义是结构正确（可顺读、图不断链），**不代表 OCR 逐字正确**——文字正确性靠抽样对照原件。
2. `python -m http.server` 起本地服务，抽查 2~3 个修复过的页面，确认视觉上不再图文重复。
3. `status.md` 全部收口，写最终总结：处理了哪些 PDF、A/B/C 各修复多少页、裁剪图多少张、遗留问题。
